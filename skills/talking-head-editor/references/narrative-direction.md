# 抽象概念、剧情推进与连续镜头

用于用户希望加强逻辑感、剧情推进、电影元素或导演剪辑手法。目标是让观众看到信息如何变化，并理解下一镜为什么出现。不要把通篇口播强制改成戏剧故事，也不要把调色、宽银幕黑边和颗粒当成叙事能力。

这些是后台编排方法，不是前台标题模板。默认让动作、对象大小、出现顺序与切点体现导演意图，避免把“建立环境、人物近景、让问题带动下一镜”等计划文字直接铺进成片。先遵守 art-direction.md 的视觉基线；新增镜头能力不应牺牲主体占幅和原声对应。总览→局部→返回是一种可选解释方法，不必每段演示；话题切换时结束该方法。

## 一段先解决一个问题

已有具体素材但变化不明显，或真人与解释画面缺少承接时，按 [状态变化与对象连续性](state-continuity.md) 设计状态、对象路径及比较层级；该方法不要求为每句话制作动画。

为解释段写出：当前问题、可见对象、初始状态、新信息或行动、状态变化、结论及限制。若原话支持，可组织成“目标→障碍→尝试→结果→修正”；若只是并列列举，用分类或对照，不制造失败和因果。

每个镜头都应回答：它新增了什么？观众接下来会问什么？下一镜怎样回应？删去不增加信息的装饰镜头。剧情推进可以来自信息逐步揭示，不要求冲突、夸张或大量转场。

| 抽象概念 | 可观察的表达 | 容易出错的表达 |
|---|---|---|
| 表达不清 | 不完整需求与补充后的需求并列，对应结果或待确认信息 | 伪造真实用户输入、模型故障或实测成功率 |
| 分工 | 具体产物：脚本、镜头安排、画面、声音；标明谁贡献什么 | 把岗位名排列成实际并不存在的上下级关系 |
| 分镜 | 至少几幅不同镜头及顺序、各镜提供的信息 | 用三分线代替分镜，或把同图裁切称为已生成新机位 |
| 构图 | 主体位置、留白、视线方向的变化和作用 | 为显专业添加无关网格 |
| 取舍/限制 | 同一对象在同尺度下呈现两种状态及代价 | 只打“困难、强大”等大字，或省略结论条件 |
| 积累/反馈 | 对象增加，或前一步产物成为下一步输入，再显示反馈 | 仅凭箭头把相关关系画成因果 |

示意情节明确标注虚构或教学示意。原声没有说出的台词不能通过字幕变成真人发言；确需新旁白时另行取得授权。案例效果来自真实测试才能称实测，演示设计不能冒充证据。

## 电影剪辑手法的使用条件

- **建立镜头→细节插入**：先让观众知道对象和空间，再取一个与当前问题有关的局部。后面可返回全貌，检查关系是否还清楚。
- **视线衔接**：人物的视线提出“在看什么”，下一镜给出对象；检查主体身份、视线方向和空间关系。它不自动等于严格的主观镜头，也不必称正反打。
- **动作匹配**：需要前后素材中同一动作的方向、阶段和位置可衔接。静态图片平移不能称人物动作匹配；缺动作素材时使用构图/形状匹配或直接硬切。
- **同一对象跨镜头**：尽量保持资产ID、裁切锚点和外观，从实例转为流程节点。目标尺寸、位置和下一段信息先设计好；不要切到重画的替代物后声称连续变形。
- **揭示与延迟答案**：先给问题对象，后给关键细节/结果；等待时长需有内容支撑，不能靠空白吊胃口。
- **反应镜头**：只使用真实或明确虚构情节内的反应。不要拿无关人物表情暗示其对某事的态度。
- **交叉剪辑**：仅在确有并行关系时使用；不要通过剪接暗示两件无关事件同时发生或互为因果。
- **J/L音桥**：声音与画面交接时可延续原声；要验证源时间、说话人和试听效果。现有示范没有验证完整声音导演设计。

建立空间后保持可辨的左右关系。AI生成多机位需要核对衣着、道具、环境和方向；一个一致的提示词不能证明所有帧身份完全一致。景别变化也不能掩盖主体换人或场景布局跳变。

## 整体→局部→整体

先布局完整世界画布、素材ID及阅读位置，再定义镜头路径。常用节奏为：总览建立关系→进入一个分支→停稳读清→进入下一分支→返回原全貌解释新关系。字幕、来源和必要标签放在屏幕层，不跟随世界画布缩成小字。

局部镜头只保留有用邻近信息。检查相邻标签被裁成半个词、推近时撞到标题、镜头移动还未结束台词已换题等问题。缩放不改变图片宽高比；越出画布或混入黑边应明确处理，不能静默拉伸。

同一对象的模糊/透明度变化是注意力设计；不把二维模糊称为真实光学调焦。需要真实人物/物体运动时准备合格视频，不把静态图片加推拉描述成AI视频生成。

## 计划与验收

沿用 editorial-plan.md 的整片语义计划。在项目分镜旁补充：`question / visible_change / new_information / next_question / asset_ids / screen_direction / transition_reason / evidence_or_illustration`。这些是编辑记录，不是 render.py 新字段。

几何执行接口见 [场景镜头工具](scene-camera.md)。结构检查通过只说明轨迹可执行，镜头是否讲清楚要在真实台词中检查。

验收重点：去掉装饰文字后，能否看懂变化？每次切换是否增加信息？前后对象是否一致？构图、分镜、动作、视线的名称是否用对？示意是否被误当实测？当前词出现与视觉变化是否合拍？需要真实动作但只有静帧时，在交付限制中说清楚。
