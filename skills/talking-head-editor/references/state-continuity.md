# 状态变化、对象承接与比较层级

用于已有相关素材，却仍出现静态配图、镜头脱节或比较对象消失的混合口播。依据 v3.0.2 的真实口播项目修订；按当前语义选择，不要求每段同时套用三种方法。字体、背景和真人表达继续遵守 art-direction.md 的基线。

## 让观众看见状态变化

先写清可见对象、初态、发生的变化和结果，再决定素材。原话只有并列或比较时，不强加因果或成功过程。删掉解释性大标题后，画面最好仍能提供有用信息。

例如拟人化“准时打卡”，可以在明确标为示意的场景中，让读卡区扫描、读取状态变为确认；变化附着在读卡器这一对象上，而不是只把“准时”放大。状态出现应跟随原话，并给结果留阅读时间。示意进度不能标成实测百分比、耗时或效率数据，真实软件演示应使用可核对的录屏。

静态图加扫描线、进度、图标和状态文字属于二维叠层。若需要手伸出、刷卡、转身等真实动作，应另备动作视频或生成合格视频；不能把图像推拉和叠层称为已经完成动作复刻。具体扫描区域和时机按素材重新定位，不照搬案例坐标。

## 让同一对象承接真人与解释画面

有回调或从实例进入解释的语义时，可让已经建立的素材先出现在真人旁，再连续改变位置与大小，进入解释画面。也可按相反方向返回真人。记录同一资产 ID、裁切锚点、宽高比、起止位置和承接的新信息；素材外观在途中保持一致。

先检查真人旁是否有空间，避开脸、手势、已有字幕和标识。没有空间时改用其他构图或硬切，不为连续性强挤小卡。背景交接和卡片运动分别安排，确保交接时卡片不消失、不突然替换，也不把原字幕与新对白叠成两层。

标题、关键词需要避开卡片整个运动路径。若路径必经文字区，可以延后标题入场或改变构图；不要仅以停稳后不重叠作为通过条件。到位后留阅读时间，原声换题时及时返回真人或下一画面。

## 次要对象仍需可辨认

当前对象更大、更清楚；作为比较依据的旧对象可退小、退到侧边或适度减弱，但保留辨认所需的轮廓与短标签。若挡住了关键部位，应先改大小和位置，再考虑模糊或透明度。旧对象不参与当前信息时可以移出，不强行常驻。

例如“磐石→车流”的比喻对照，车流成为主角时仍保留可识别的磐石，而不是新卡把旧卡几乎盖完。用手机尺寸预览确认两者身份清楚；不固定左右方向、卡片比例、颜色或边框样式。非定量构图的大小差异不能冒充数量比例。

## 复用与验收

- 在项目计划记录变化时点、对象 ID、运动路径、比较对象需要保留的部位，以及返回真人的语义位置。这些是制作记录，不是 render.py 新 JSON 字段。
- 按需使用 editorial-motion.md 的照片合成、scene-camera.md 的二维轨迹，或项目专用合成脚本。案例脚本依赖业务素材，不能原样复制进技能后称为通用工具。
- 检查运动前、途中、到位、退出和硬切两侧。重点看标题碰撞、卡片跳位、裁切和双字幕；比较新旧版同一台词与时点。先看实际运动再判断节奏，抽帧证据单独记录。
- 仅更换视觉时保留已检查音轨，核对解码音频一致性；修改声音或剪口则重新复核。音频一致不等于已经完成主观听审。
- 把技术结果、选帧观察、完整视听及参考风格认可分开记录。未经用户认可的效果仍称候选，不报无依据的复刻比例。

验证范围与项目时间点见 [验证记录](validation.md) 的 v3.0.2 节。
