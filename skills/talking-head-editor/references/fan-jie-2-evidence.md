# 《反解2》参考证据与解释段落写法

用于用户选择《反解》系列风格，特别是概念对照、流程说明、多案例讲解时。源视频 319.32 秒，1280×720，约 30fps，有音轨。依据为全片每 4 秒抽帧、11 组加密抽帧及本地机器转录；01:50 的缩小过程按约 0.083 秒取样。未完整逐句试听，未核实片中技术、企业、实验数值或资料来源。

这是 v2.9.1 的参考学习规则，不表示新增了相应的一键渲染接口。全文时间是源视频定位；除明确加密检查的缩放外，其余不当作逐帧剪点。

## 六种解释段落

这些是编排方法，不是新增 JSON 效果名。可写进 v2.9 计划的 takeaway/focus/entry/exit 和素材标识，再用现有合成工具或项目脚本实现。

1. **熟悉概念→新概念**：旧对象建立→新对象进入→共同处/差异出现→旧对象退为次要→新对象成为焦点。保留可识别的形状与标签，低对比或模糊不能抹掉比较对象。
2. **以前的工作→新的处理方式**：真人说明原来要做哪些事→少量工作卡逐项出现→新结构接手→给出具体变化。内容不支持效率数据时不造数字或进度条。
3. **全貌→分支→回全貌**：先给结构骨架→只展开正在解释的分支→局部读清→回到同一结构。先设计整个画布与各阶段焦点，再移动视窗；避免局部漂亮但返回时关系错位。
4. **实例→流程**：先让观众看见对象或动作→同一画面退成卡片→连接流程起点→当前步骤逐个强调→结果→回真人判断。缩小时识别信息保持稳定，完整对白不随图一起缩成小字。
5. **数字比较→资料局部**：同一视觉单位展示比较对象→关键数值进入→对象卡迁移到资料旁→突出原文相关句→保留单位、条件、日期和来源。装饰点阵不自动代表精确样本数；无法说明映射时标为装饰或换图形。
6. **问题→结果→纠错**：给问题对象→过程如何发生→不理想结果→真人判断/转折→展示纠正行动。只有源话支持因果时才画因果链，纠错后保留仍然存在的限制。

## 统一对象，变化版式

同一素材在多个镜头出现时使用稳定 asset ID。首次建立外观后，后续主要改变位置、大小、清晰程度和显现信息；无理由重画对象会丢失视觉记忆。跨场景的源视频时间、照片裁切与标识要保持可辨认。

主次改变不一定要换镜头。可以缩小/退后旧对象、压低其对比或对该层预先模糊，并让新对象清楚稳定。当前 photo_card 支持平面卡与透明度；逐卡模糊和整图镜头路线需项目合成，不将其写成基础 render.py 不支持的参数。

参考片的橙、蓝、红、绿色承担不同任务；不要固定所有关键词为绿色。先确定两种背景材质、常规字/重点字/对白层级，以及重点和对比色，具体数量按项目决定，不硬凑完整“色板”。

横屏真人旁的小卡迁移到竖屏时，先检查人物占位。必要时改为全屏解释后回真人；不要把几张横屏卡挤在头顶。内部小字的作用若只是识别素材，就不要同时要求观众阅读。

## 现有能力与缺口

已有：二维卡片、局部聚焦、连线、源时间关键词、全片计划与审片队列。短片验证不等于自动完成整段解释。

待专门实现/验证：大型关系图多视窗调度、同对象跨场景的成套可复用镜头、完整数值/过程卡母版、精细人物分层、复杂粒子/三维原创画面，以及完整声音审片。可叠入有适当来源的现成复杂视频，但这不代表工具会生成该类画面。

参考中资料展示已见到，无法仅凭成片判断录屏还是截图动画；素材是否 AI 生成、粒子使用何种软件、具体音乐与音效来源均未确认。
